## Batch summary

Dominant failure class: **parse_or_tool_call_error via edit-target/binding resolution** — `resolve_target` (`vibecomfy/executor/edit_tools.py:262-290`) rejects every reference the agent legitimately takes from the render (raw graph numeric ids like `28`/`115`/`2`, class-derived names like `rodin3d_regular`/`vaedecodeaudio`, and even freshly added nodes' binding names), because the single resolution authority knows only `uid_by_name` (from `_compute_variable_names`) plus IR uids/node-keys, which do not match the render vocabulary for these graphs. This defect is the primary cause in 4 of 6 scenarios (3d-converts, 1b1360, and the edit attempts inside cc0df7 and 8800a9), and it is the highest-leverage fix: **one binding authority** — emit the render/lens and `resolve_target` from the same name/uid source (and/or add a class-name fallback plus raw-id→IR-id mapping in `resolve_target`) — so the agent's repeatedly-correct diagnoses actually land. Secondary fixes: (1) make host-action parse failures retryable instead of fatal — `agent_backend.py:815-818` hard-fails on one malformed model response and thereby erased an accepted, correct edit in 3d-generates (the only judge_or_harness_bug of the batch, and the only scenario where the agent's work was lost after success); (2) actually engage the declared continuation partitions (`two_step.py:705-713`, `agent_backend.py:973`) — zero `purpose_denied` events were observed and research exhausted all 64 continuations in 8800a9; (3) surface the `requires_custom_nodes`/safe-refusal outcome kind to the model so justified blocks (cc0df7) and vacuous refusals (f0859f) are scored honestly instead of as empty-Δ failures. Finally, the batch digest is not trustworthy as-is (fabricated criteria for two sections, one missing section) and should be regenerated from assessment.json + transcripts before being used for scoring.

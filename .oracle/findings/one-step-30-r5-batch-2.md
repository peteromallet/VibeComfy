## Batch summary

Dominant failure class: **judge_or_harness_bug — the edit-session ingest door silently empties the graph** (5 of 6 scenarios). In every edit scenario the agent held the correct diagnosis, targeted the right node with the right value, and used the typed tools with every legal reference form (render binding names, class names, bare uids, `uid:NNN`) — and the resolver rejected them all ("Unknown graph name 'X'…", "no node in the current render resolves to 'X'") because `EditSession`'s IR is empty: `_workflow_from_ui` (`vibecomfy/porting/edit/_gates.py:300-307`) hardcodes `from_ui(use_comfy_converter=False)`, which returns a 0-node workflow for both graph formats in this batch (reproduced locally: `from_ui(converter=False)` → 0 nodes for envelope and bare-api, while `from_envelope`/`_named_import` → 6/11/21/12/20/15). The render door the agent reads (`_two_step_graph_render`, `two_step.py:1350-1358` → `_coerce_workflow`, `render.py:110-125`) uses the correct dispatch, so the agent sees a real graph while editing against a ghost — an authority split that violates philosophy #1/#2. After two rejections, `edit_tools.py:581-587` locks the session to `second_rejection_no_candidate`; agents then burn the continuation budget and submit `graph_unchanged=true`, and the judge — correctly — fails the empty Δ. The single highest-leverage fix is to route `_workflow_from_ui` through the same `_named_import`/`normalize_to_api` dispatch the render path uses (envelope → `from_envelope`, list-nodes → `from_ui`, else `normalize_to_api`/`from_api`), and add a fail-closed guard: an ingest that yields 0 nodes from a non-empty graph must raise (philosophy #4/#12) instead of silently accepting edits against nothing. Secondary fixes: (a) the response assembly (`vibecomfy/agent/artifacts.py:375-397`) must not project `final = original` when `accepted_delta_ids` is non-empty — the judge's comparison surface must be able to see a landed edit; (b) for the research route, raise/decouple `session_model_continuations` from multi-window re-research so a substantive answer can be submitted instead of a budget stub (scenario 5).

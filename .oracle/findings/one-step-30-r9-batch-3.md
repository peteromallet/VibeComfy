## Batch summary

The dominant failure class in this batch is **judge_or_harness_bug — the G0R `landed_operation_count` guard reads a field the executor never writes** (`assessor.py:802-831` reading `change_details.landed_operation_count` while the executor's terminal projector emits `accepted_batch`/`accepted_delta_ids` and no `change_details` at all: `two_step_session.py:1464-1494`, `contracts.py:2608-2623`, `agent_backend.py:1094-1098`). It is decisive in 2 of the 5 scenarios (`image-style-transfer-using-ip-adapter`, `multi-3d-preview-and-image-output-workflow-d93baf`), where the semantic intent judge **passed** every criterion and the only error is the mechanical count — across the whole r9 run, all 11 landed-edit responses (graph_unchanged=false) carry zero `change_details`, so this one guard fails every landed edit. The other three scenarios are genuine agent failures of the same classes seen in earlier rounds: `edit_quality` (image-editing-with-qwen landed a link whose mechanism it self-reported as unverified, which does not implement lighting matching), `refusal_or_block`/grounding-gate placeholder (sharpening — the deterministic gate still destroys the real answer and substitutes its own violation text), and `grounding_or_evidence` (inpainting — named widget labels `start_percent/end_percent/strength` not backed by retained node evidence).

**Single highest-leverage fix:** make the G0R guard read the executor's actual landed-Δ authority — derive the count from `accepted_batch`/`accepted_delta_ids` (or have the terminal projector emit `change_details.landed_operation_count = len(accepted_batch)` at `two_step_session.py:1464-1494`) instead of requiring a `change_details` key no component produces. That one contract fix flips both judge-confirmed scenarios in this batch (and every landed-edit scenario in the run) from fail to pass, and it restores the measurement's ability to see a landed edit (philosophy #1/#11: the judge's comparison surface must be able to see a landed edit).

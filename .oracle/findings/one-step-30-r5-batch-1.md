## Batch summary

The dominant failure class in this batch is **judge_or_harness_bug, not model capability**: 5 of the 6 failures (all five edit scenarios) share one code-level root cause — the edit tool's retained IR is silently empty. The render/lens path (`vibecomfy/porting/render.py:110-144`) routes the Vibe-envelope request graph through the correct door (`detect_workflow_shape` → `from_envelope`, 46 nodes), so agents saw correct binding names and uids and produced correct, well-targeted edit statements (UltraShapeRefine → 0.4, Rodin3D_Regular → Polygon_count, VoxelToMeshBasic → threshold, AudioFilter/remove_hiss insertion after VAEDecodeAudio). But `EditSession.__init__` (reached via `two_step.py:1099-1101`) ingests the same graph through `_workflow_from_ui` → `from_ui(use_comfy_converter=False)` (`_gates.py:300-307`), which silently returns a **0-node workflow** (reproduced for all 6 request graphs; `from_envelope` gives the full node count). Every edit op then fails `unknown_target`/`unknown_graph_name`, the agent misattributes the failure to stale bindings, no Δ ever lands, and the judge — grading the empty accepted Δ — fails the scenario. Scenario 2's budget exhaustion and scenario 4's final-action parse error are downstream of this same bug (research loops after rejected edits; a malformed final action JSON). Scenario 6 (DetailDaemon) is the only genuine agent-output failure, and even it is a measurement conflict: the grounding gate + explicit prompt constraint ("give NO numeric recommendations" without evidence, prompts.py:829-835) forced the agent to strip the substantive answer the rubric demands, with no schema/registry evidence available for the node.

**Single highest-leverage fix:** make the EditSession ingest format-aware — route envelope graphs through `from_envelope` (use the existing `_named_import`/`detect_workflow_shape` logic, or pass `initial_workflow=from_envelope(graph)` in `_two_step_edit_session` at `vibecomfy/executor/two_step.py:1359-1368`), and make `_ui_graph_to_api`/`from_ui` **fail closed** (raise on unrecognized shapes) instead of silently returning an empty IR — one authority for both the lens and the edit tool. Secondary fixes: route content-grounded "no_change" refusals (e.g., a refusal whose text is a `requires_custom_nodes` case) through the grounded-refusal judge (`assessor.py:719-731`), and reconcile `_GROUNDING_CONSTRAINT` with the semantic-answer rubric so a Q&A answer may give hedged, clearly-flagged recommendations when the node pack lacks schema coverage.

## Batch summary

**Dominant failure class: `judge_or_harness_bug` — 6/6.** The judge failed every scenario correctly *given the artifacts*, but the artifacts were wrong in two systemic ways, both harness-side at commit `bcf92497`: (1) **Dead edit tool** (4 scenarios: `3d-3d-model-generation…`, `3d-3d-shape-generation…`, `3d-converts-image-to-3d-model`, `audio-acestep…`) — the one-step door hands `EditSession` the IR-envelope/raw request graph, which `from_ui` cannot ingest (`normalize.py:526` expects a LiteGraph `nodes` list; envelope `nodes` is a dict, so the comprehension yields nothing) ⇒ the retained IR has 0 nodes ⇒ every target — class name *and* numeric uid — raises `unknown_target` (`edit_tools.py:287-290`) / `unknown_graph_name` (`_resolve.py:1447`). I reproduced this at `bcf92497`: `EditSession(request.graph)` → 0 nodes, `resolve_target('2')`, `'28'`, `'115'`, `'ultrashaperefine'`, `'rodin3d_regular'`, `'vaedecodeaudio'` all raise. (2) **Accepted-Δ loss** (2 scenarios: `3d-generates-a-3d-mesh-from`, `audio-…-chatterbox…`) — the agent landed the correct, intent-matching edit (`Δ=d1`; threshold 0.6→0.8 on VoxelToMeshBasic; SaveAudioMP3→SaveAudio with WAV wiring), but the terminal response discarded it (`unknown host action None` failure path, or a stale no-change reply), `graph_unchanged=true` forced `final.ui.json = original` (`artifacts.py:384-398`), and the judge graded an empty diff. Both are pure harness defects: the agents' edits were correct in 2/6, their diagnoses correct in 5/6, and their failures (budget burn in `…8800a9`; refusal mislabeling in `…cc0df7`) are secondary overlays on a broken edit surface.

**Single highest-leverage fix:** make the one-step execute door feed the edit session a graph the `bcf92497` ingest can actually parse — convert `request.graph` (envelope/raw forms) to LiteGraph before `EditSession` at `two_step.py:1098-1101` (or make `from_ui`/`_normalize_ui_to_api` accept dict-`nodes` envelopes) — **and** preserve the accepted Δ + replayed graph into the terminal response on every exit path (failure envelopes included), which is exactly what the follow-up commits `99d9ca18` (RC-P2 terminal projection) and `d04aa211` (RC-P3 continuation partitioning) implement. Until the accepted Δ and the emitted `final.ui.json` are guaranteed to reflect the session's landed edits, no model-capability change can move this score: 6/6 of these failures are measurement/harness, not judgment.

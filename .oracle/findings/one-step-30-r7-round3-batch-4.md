### multi-3d-preview-and-image-output-workflow-d93baf
- Judge verdict: FAIL (`correct_node_targeted: false`, `correct_parameter_changed: false`, `no_orphaned_wiring: true`, `value_semantically_matches_intent: false`)
  - assessment.json rationale: "The accepted Δ contains no batch statements (checked: 0, mismatches: []), and both pre/post views show 'No changes', so SaveGLB's filename_prefix was never updated to '3d/moge-top-down'; the graph remains structurally connected only because nothing was edited." Plus `graph_changed` issue: "Expected graph change but response.graph_unchanged is True."
- What the agent did: correctly diagnosed the exact intent (query: "Change the SaveGLB filename prefix from '3d/ComfyUI' to '3d/moge-top-down'. Keep the mesh input and both normal-map preview branches unchanged."), fetched `node_schema-saveglb` repeatedly, attempted the filename_prefix edit, and every attempt was **rejected by the editor** — 52 model continuations, 36 tool calls, 2 replacement attempts, 1975s wall clock. Final reply: "All SaveGLB filename_prefix edit attempts were rejected (target unresolved / no candidate), and no further edit attempts are allowed this session. No accepted Δ exists." (`self_assessment.outcome = "no_change"`, honest submit).
- Why it failed: not agent capability — the agent's diagnosis and edit intent were exactly right and are what the judge itself names as the required change. The typed-edit resolution layer rejected the target (`no_candidate_reason="route_not_applyable"` at response level, driven by `unresolved_schema_terminal` → `_frag_response_contract.py:1074-1082, 1218-1224`). Note SaveGLB's schema **is** present in the local object_info cache (`vibecomfy/porting/cache/object_info/comfy_core@object_info_comfyui_0.24.0.1.json` has `SaveGLB.filename_prefix`), so "schema unavailable" is not the true cause — the session's resolution surface simply did not expose the node.
- Class: **judge_or_harness_bug** (tool-validation layer rejected a correct, schema-backed edit; agent behavior was exemplary and honest).
- Root cause (code-level): edit-target resolution fails when the edit session's workflow is not resolvable — `resolve_target` raises `unknown_target` when `edit_session.workflow` is None/empty (`vibecomfy/executor/edit_tools.py:262-290`), and the one-replacement window then hard-stops at the second semantic rejection (`EditToolRuntime.dispatch`, `edit_tools.py:581-587`, reason `second_rejection_no_candidate`). Empirically: `ingest_workflow_and_ui()` of this request graph yields node uid `'21'`/SaveGLB and `resolve_target(session,'21')` succeeds when the workflow is hydrated, and fails with exactly "no node in the current render resolves to '21'." when it is not — i.e., the harness session's IR was not wired into the tool's resolution index (bcf92497 regression surface).
- Evidence: response.json `message`: "The edit to set filename_prefix to '3d/moge-top-down' was not accepted by the editor, so no graph change was made this session."; `budget_usage: {apply_batches: 0, model_continuations: 52, replacement_attempts: 2}`; final.ui.json == original.ui.json (8 nodes, 4 edges).

## Batch summary

**Dominant failure class: judge_or_harness_bug — 5 of 6 scenarios (d93baf, 1a7f84, multi-image-to-video-generation-with, multi-image-to-video-with-llm, bd3afb) had a correct, well-grounded diagnosis and an attempted graph-local edit that the harness rejected** (`unknown_target` / "no candidate" / `second_rejection_no_candidate` → `no_candidate_reason: route_not_applyable`, `graph_unchanged: true`, empty `accepted_batch`). The 6th (multi-crops) is a genuine refusal/clarify (agent asked for a target path instead of acting; scenario allowed no safe-refusal kind). The judge's Δ-empty verdicts are correct in all 6; the failures are upstream of the judge, in the edit-resolution layer, not in the model's judgment — the replies are consistently the best evidence in each transcript, and `resolve_target` demonstrably resolves the very uids the harness rejected when the session's workflow is hydrated (empirically verified for KSampler uid '3'; SaveGLB's schema exists in the local cache).

**Single highest-leverage fix:** hydrate the typed-edit resolution surface from the retained IR that the agent already sees — i.e., ensure `EditSession.workflow`/`uid_by_name` (`vibecomfy/executor/edit_tools.py:262-290`) is always populated from `AgentEditState.workflow` at session start (the bcf92497 "retained IR" is currently readable but not resolvable), and build the post-apply lint index (`edit_batch_repl.py:1538`, `LintIndex.build(state.graph)`) from the emitted UI/IR payload rather than the raw request graph, which yields **0 nodes for every graph serialization in this batch** (verified empirically). That one change unblocks 4/6 scenarios outright; bd3afb additionally needs a provisional-schema source for classes like `ImageFromBatch` (existing `gen_hard_missing_schemas` workstream), and the `uid_by_name` map should also accept class-type names (e.g. `KSampler`) so "names over indices" (philosophy #9) works for API-format graphs. Secondary: fix the digest/judge narrative surface — its "Δ removed all nodes / 0-node topology" rationales for d93baf, bd3afb and multi-image-to-video-generation-with contradict the byte-identical original/final UI artifacts (philosophy #12: honest evidence, always).

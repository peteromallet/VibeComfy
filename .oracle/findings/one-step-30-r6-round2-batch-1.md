## Batch summary

Dominant failure class: **harness edit-target resolution mismatch** — in 4 of 6 scenarios (3d-3d-shape-generation-and-export-workflow-8800a9, 3d-converts-image-to-3d-model, 3d-generates-a-3d-mesh-from, audio-acestep-audio-generation-and-processing-workfl-1b1360) the agent produced a correct, graph-grounded edit (right node, right field, right value — the judge itself credited `correct_node_targeted: true` in the UltraShape case) and the run-time edit session rejected every render-visible target (`# uid:28`, `rodin3d_regular`, `ultrashaperefine`, `vaedecodeaudio`, `115`, `62`…) with `unknown_target`/`unknown_graph_name`, while the current checkout resolves all of those names. The precise hydration divergence (which revision the run-time EditSession was built from vs the one used for the prompt render) is not reproducible from this checkout — the mechanism and rejection sites are pinned (`resolve_target` vibecomfy/executor/edit_tools.py:262-290; `_resolve_graph_name` vibecomfy/porting/edit/_resolve.py:1419-1445; 2-rejection `second_rejection_no_candidate` latch edit_tools.py:581-587) but the triggering state divergence is marked `unknown_needs_human` for verification in the run environment. Secondary contributors: offline schema-coverage gaps (Rodin3D_Fusion, AudioFilter/DetailDaemon — confirmed by `.oracle/results/one-step-30-r6.json` "offline schema coverage for custom node classes…"), research-loop budget death (64-continuation cap, Hivemind 57014 timeouts, 3d-3d-shape-generation), a host-action parse failure that dropped a landed Δ from the judged artifact (3d-generates-a-3d-mesh-from, agent_backend.py:408-423 + failure-path response assembly), and one genuine model-behavior refusal (detail-daemon).

Single highest-leverage fix: **make the edit-tool resolution surface identical to the render surface** — build the retained EditSession from the exact graph revision whose render text is injected into the prompt (or resolve targets against the render's own name/uid map), and fail loudly if the session IR and the rendered revision diverge; plus a stop-loss guard: report unknown `add_node` classes and unknown targets as terminal, non-retryable errors so the one-replacement window and the continuation budget are not consumed proving the same mismatch three times.

# R8 — Terminal Cleanup, Proof Audit, and Completion Manifest

## Outcome

Remove all residual architectural debris, directly prove every North Star and
cleanup condition against current source and R7 runtime evidence, populate the
proof map, and emit the fresh content-addressed completion manifest.

## Input handoff

- R7 pinned environments, exhaustive real-Comfy lifecycle matrix, attribution,
  CI evidence, and acceptance.
- R6 recovery/Undo/legacy matrix and crash/restart evidence (mandatory direct input,
  not inferred from R7 summaries).
- R1–R5 accepted implementation, ownership, deletion, verifier, and controller proofs.
- M0/M1 predecessor proof and the current North Star.

R8 must not start if R7 or R6 evidence is missing, stale, indirect, or does not
match current source and environment hashes.

## IN

- Audit and delete remaining duplicate owners, copied canonicalizers, dead
  imports/exports, fallback native mutation, stale compatibility facades, title
  identity, scanner exclusions, obsolete helpers, and misleading comments/docs.
- Audit every typed request/response adapter and reconstructed payload on the
  mutation path against the R5 authority-field ledger. Reject silent field
  loss, permissive extra-field dropping, parallel partial DTOs, or handwritten
  forwarding lists that can diverge without a contract test.
- Audit executable deployment provenance as well as source ownership: exactly
  one resolved backend root, one route-registration winner, and one frontend
  asset set may be active. Silent first-import-wins skips and dynamic Git
  metadata that can disagree with loaded bytecode fail the terminal audit.
- Delete the alias/canonical Python namespace split and prove no reachable
  module realpath is loaded under multiple authority-bearing identities. The
  temporary `/accept` bridge must be deleted or remain pure delegation with
  zero comparison, lock, receipt, or baseline authority.
- Retain `migrateFingerprintScopedSessionId` only as the declared
  `workflow_chat_scope_binding_v0_fingerprint_to_v1_uuid` migration until its
  migration-ledger age-out: at least 30 days, two released versions, zero
  successful v0 reads for the full interval, and a reviewed version bump;
  then delete it through that migration contract rather than treating it as an
  unexplained shim.
- Prove the source-derived ledger has zero open S3/S4/migration-debt rows and
  exactly matches production source in both directions.
- Prove `vibecomfy_roundtrip.js` contains only bootstrap, event wiring, and view
  composition; enforce this with a static responsibility gate.
- Re-run all architecture ownership, `.js`/`.mjs`, stable identity,
  browser/Python parity, recovery coverage, and required R7 real-Comfy CI gates
  after cleanup.
- Conduct an independent adversarial nine-point audit, requiring direct evidence
  for each North Star condition and rejecting wrapper, allowlist, self-attested,
  reduced-fixture, absence-only, or mock-only proof.
- Populate every milestone proof-map path with current SHAs, commands, outputs,
  environment hashes, and content artifacts; create a final proof index.
- Generate and validate `completion-manifest.json` from the current chain,
  North Star, briefs, chain state, proof map, and hashed proof artifacts.

## OUT

New features, nested scopes, universal compatibility, arbitrary manual repair,
or unrelated repository cleanup.

## Locked decisions

- Cleanup is a release requirement, not optional polish.
- A compatibility shim survives only if it implements an explicit versioned
  migration contract and is named in the final audit.
- Static ownership rejects graph fingerprints appended to workflow/chat
  identity, compatibility/session CAS hashes used as typed witnesses,
  finalized composer notices, and arbitrary logical-field writes to JavaScript
  node properties when a native widget owns the field.
- Static ownership rejects free-floating panel receipt/generation/lease fields
  and any reconciliation path that merges transaction evidence without an
  exact session/turn/transaction ownership check.
- Static ownership rejects semantic widget-index inference from serialized input
  descriptor ordinals and any compensation path that treats a preflight failure
  as a started canvas mutation.
- Green tests do not prove completion unless their scope directly covers the requirement.
- Manifest generation is terminal evidence, not a substitute for the audit.
- Protected files are excluded from staging and manifest inputs.

## Open questions for the planner

- Whether each residual compatibility branch is a declared migration or dead debt;
  require affirmative versioned evidence or delete it.
- Any proof-map item whose existing evidence is weaker than its stated scope;
  gather direct evidence rather than weaken the claim.

## Constraints

- Preserve product behavior and every R7/R6 proof while deleting debris.
- No broad allowlists, responsibility wrappers, or “must stay in sync” duplicates.
- All proof artifacts must exist, be current, and be hashable before manifest generation.

## Done criteria

- Repository-wide cleanup finds no unjustified duplicate/dead owner, export/import,
  fallback path, shim, canonicalizer, identity heuristic, scanner bypass, or stale doc.
- Static and composed gates prove no authority field can be accepted at HTTP
  ingress and then disappear at an executor/controller/session projection.
- The declared fingerprint-key migration remains explainable and tested until
  age-out, including v1-wins/malformed/no-broad-search semantics; getter-only
  layout properties remain adapter-owned and unwritten.
- No descriptor-ordinal widget mapper or unconditional preflight compensation
  survives; auxiliary-widget and zero-mutation evidence remains green.
- Zero open S3/S4 rows; scanner and ledger exact both directions.
- Roundtrip passes its composition-only responsibility gate.
- All R7 composed lifecycle and R6 recovery evidence remains green after cleanup.
- Every one of the nine North Star conditions has direct current proof; independent
  adversarial audit reports no false-completion pattern.
- Every proof-map entry is populated by an existing authoritative artifact.
- Full repository check and diff check pass.
- `megaplan chain manifest --spec ... --proof-map ...` emits a fresh valid
  `completion-manifest.json` matching all current hashes and completed milestones.

## Touchpoints

All agent-edit browser/server ownership surfaces, roundtrip, ledger/scanners,
exports/imports, migration paths, docs/comments, CI/static guards, proof directory,
proof map, final audit, and manifest tooling.

## Anti-scope

No new capability, nested implementation, universal support claim, waived proof,
indirect summary in place of R6/R7 evidence, broad allowlist, protected-file
change, or completion declaration before manifest validation.

## Output handoff and proof artifacts

- Terminal cleanup/deletion/dead-export/duplicate-owner audit.
- Final nine-point adversarial audit and proof index.
- Fully populated manifest-compatible proof map.
- Fresh validated `completion-manifest.json`; this is the epic terminal handoff.
